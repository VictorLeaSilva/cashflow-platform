## Como os comandos foram executados
- **Dois clones limpos** do branch `task/T-007-readme-executavel`, no *scratchpad* (fora do OneDrive, com `core.longpaths`, porque o caminho passa de 260 caracteres): um para o bash (`rb`) e outro para o PowerShell (`rp`). Assim, `.env`, `deploy/dev-keys/` e a compilação partem do zero, como para quem acabou de clonar.
- **Stack isolada** em cada *shell*, para não tocar na stack `fluxo-caixa` do autor (que estava rodando, com o serviço de Lançamentos dele, PID 28812, na porta 8081):
  - `COMPOSE_PROJECT_NAME=readme-teste-bash` e `readme-teste-ps`;
  - portas trocadas no `.env` de teste: PostgreSQL 55432/55433 e Kafka 59092/59093;
  - os serviços subiram com `SERVER_PORT=18081` e `18082`.

  **Fora isso, os comandos são os do README.** As saídas do README são as destes testes, resumidas.
- **Ao fim:** só os processos das portas 18081/18082 foram encerrados, por PID, e os dois projetos isolados foram removidos com `down -v` (0 volumes `readme-teste*` restantes). A stack `fluxo-caixa` seguiu de pé, sem mudança.
- **Efeito colateral:** o `mvnw install` instalou os artefatos do projeto (`br.com.fluxocaixa:*`) no `~/.m2` do autor. Isso não muda nada no repositório; é justamente o que destrava a subida do Consolidado (achado 1).

## Achados que mudaram o README (todos confirmados na execução)
1. **O Consolidado não sobe sem `mvnw install`.** `-pl consolidado-service spring-boot:run` falha com `Could not find artifact br.com.fluxocaixa:contracts:jar:0.1.0-SNAPSHOT`, porque o artefato `contracts` (T-022, Q-043) não está no repositório local. O README ganhou o passo 5. A instrução dada antes ao autor, de subir o Consolidado para criar as tabelas, falharia sem esse passo.
2. **Os serviços não sobem num clone limpo antes do `DevToken`.** O profile `local` lê `deploy/dev-keys/jwt-public.pem`, e quem cria a pasta é o `DevToken` na primeira execução. O erro é `chave pública JWT ilegível em file:../deploy/dev-keys/jwt-public.pem`. O README gera a chave no passo 6, antes dos serviços.
3. **No PowerShell 5.1, um JSON direto na linha chega malformado** (400 `json-malformado`). Por arquivo (`-d "@credito.json"`), funciona.
4. **No PowerShell, `bash` é `C:\windows\system32\bash.exe` (WSL).** O `verify-local.sh` é chamado pelo caminho do Git Bash.
5. **Acento no corpo, pelo Git Bash do Windows** (`"Venda balcão"`), dá 400 `json-malformado`. Os exemplos não têm acento.
6. **Consistência eventual visível:** uma consulta do período feita logo depois do crédito retroativo ainda não o mostrava; um instante depois, mostrava. O README pede 1 a 2 segundos de espera.
7. **ID vazio no estorno responde 401** (a rota vira `/error`). O README avisa disso no 9.4.
8. **O `--retry-all-errors` do curl repete também nos 401** e prendeu a minha espera pela porta. Só afetou o teste; o README não usa essa opção.

## Decisões para o revisor
1. **Q-054 (em proposta):** a regra está no `AGENTS.md` e no `05-harness.md`. Se o autor escolher outra opção, esses dois arquivos e a seção do README mudam.
2. **Três terminais**, em vez de rodar os serviços em segundo plano: para um iniciante é mais fácil acompanhar e desligar, e o log de cada serviço fica visível.
3. **Um token com os três *scopes*** no passo 6, para não precisar gerar outro no meio do caminho. Os *scopes* são explicados e o 403 aparece na tabela de problemas.
4. **Fuso de São Paulo nas datas:** `TZ=America/Sao_Paulo date` no bash e `ConvertTimeBySystemTimeZoneId(..., "E. South America Standard Time")` no PowerShell, porque a `dataReferencia` é calculada nesse fuso (`03 §4.1`). No macOS, `date -v-3d`.
5. **Nenhuma mudança de código, compose ou script:** os achados 1 e 2 foram resolvidos na ordem dos passos, como manda a T-007. Um `scripts/demo.sh` e o profile `apps` continuam na T-035.
