## 1. Critérios de aceite

Comandos, a partir de volumes vazios (`down -v` antes):

```bash
cp .env.example .env
docker compose --env-file .env -f deploy/docker-compose.yml up -d --wait
deploy/verify-local.sh
```

## 2. Verificações adicionais
- **Falha cedo sem senhas:** `docker compose --env-file <vazio> ... config` termina com exit 1, listando as cinco variáveis obrigatórias.
- **Schema `public`:** `has_schema_privilege('lancamentos_app','public','CREATE') = false`; para `lancamentos_owner`, `true`.
- **O script detecta falha:** na primeira execução, o `describe` com dois `--topic` fez o `kafka-init` sair com 1 e o `verify-local.sh` reportou 3 falhas (exit 1). Corrigido com `--topic` em regex; a reexecução passou.
- `bash -n` nos dois scripts sem erros. `shellcheck` não está instalado nesta máquina (fica para o job de CI da T-035).

## 3. Achados e impactos em outras tarefas
- **Git Bash no Windows** converte argumentos como `/opt/kafka/...` em caminhos do Windows; o `verify-local.sh` exporta `MSYS_NO_PATHCONV=1`.
- **T-011:** como o SQL lê as senhas por `\getenv`, o PostgreSQL do Testcontainers precisa receber as quatro variáveis `*_OWNER_PASSWORD`/`*_APP_PASSWORD` (`withEnv`), além de copiar `deploy/init/`. Ajustar o texto da T-011 antes de executá-la.
- `PlatformCompatibilityTest` usa `postgres:17-alpine` (tag flutuante da mesma linha); o compose pina `17.11-alpine`. A T-011 deve usar a tag pinada.
