## Objetivo
Pedido do autor, em 2026-10-24: o README principal deve permitir subir e usar a aplicação do zero, copiando e colando os comandos na sequência, em **bash** (Linux, macOS, Git Bash) e em **PowerShell** (Windows). Para cada comando, ele deve dizer para que serve e o que se espera de resultado. O documento também precisa continuar vivo nas próximas tarefas.

Hoje o README só sobe o Lançamentos, em bash, e não explica que as tabelas são criadas pelo Flyway na subida de cada serviço. Com isso, o banco `consolidado` da stack local do autor está vazio. O Status do README também está parado na T-013.

## Decisões da tarefa
### Conteúdo do README
- **Pré-requisitos:**
  - JDK 25 e Docker Desktop (ou Docker Engine) com Compose v2;
  - `curl` (no PowerShell, sempre `curl.exe`, porque `curl` é *alias* do `Invoke-WebRequest` no Windows PowerShell 5.1);
  - no Windows, o Git Bash para o `verify-local.sh`.
- **Passo a passo numerado, do zero:**
  1. criar o `.env`;
  2. subir a infraestrutura;
  3. verificar a infraestrutura;
  4. carregar o `.env` em cada terminal;
  5. subir o Lançamentos (terminal 1);
  6. subir o Consolidado (terminal 2);
  7. gerar o token;
  8. registrar, repetir e estornar lançamentos;
  9. consultar lançamentos;
  10. consultar o consolidado;
  11. abrir a Swagger UI;
  12. conferir os bancos;
  13. parar e limpar.
- **Cada passo** traz para que serve, o bloco bash, o bloco PowerShell e **o que se espera** (saída resumida, status HTTP, campos do JSON). Os comandos são os mesmos nos dois *shells*, só com a sintaxe trocada.
- **Bancos:** explicar que bancos e roles nascem do `deploy/init/` no primeiro `up`, e que as **tabelas** nascem do Flyway na primeira subida de cada serviço. Explicar também o que acontece com `down` e com `down -v`, e a ressalva da retenção do tópico (7 dias) para um Consolidado que sobe tarde (ADR-006).
- **PowerShell:**
  - JSON do corpo enviado por arquivo (`-d "@arquivo"`), o que funciona igual no 5.1 e no 7.x, que tratam as aspas de forma diferente;
  - entrada por *pipe*, porque o PowerShell não tem `<`;
  - `"-Dspring-boot.run.profiles=local"` entre aspas;
  - `.\mvnw.cmd`.
- **Solução de problemas:** porta ocupada, Docker parado, token vencido (401), 403 por *scope*, consolidado ainda vazio (consistência eventual), `.env` não carregado.
- **Status atualizado:** M0 parcial (T-003 pendente), M1 e M2 completos, próximo a T-030.
- **Seção curta "Manter este README vivo"**, que aponta para a regra da Q-054.

### Verificação dos comandos
- Todo comando do passo a passo é **executado** pelo implementador, nos dois *shells*, numa stack **isolada** (`docker compose -p <outro nome>`, portas alternativas por variável), nunca na stack `fluxo-caixa` do autor. As saídas reais alimentam o "o que se espera".
- A evidência registra o *shell*, a versão e o resultado de cada passo. O que não puder ser executado fica marcado como não verificado.

## Critérios de aceite
- **AC-T007.1** Seguindo o README do zero numa stack isolada, os dois serviços sobem e as tabelas dos dois bancos existem depois da primeira subida. Um crédito, um débito, um *replay* idempotente e um estorno respondem conforme o "o que se espera", e o consolidado do dia reflete os lançamentos. Isso vale em bash e em PowerShell.
- **AC-T007.2** Cada comando do passo a passo tem as versões bash e PowerShell, um texto curto de para que serve e um "o que se espera" que confere com a saída real registrada na evidência.
- **AC-T007.3** O README explica de onde vêm os bancos, os roles e as tabelas e o que acontece em `down` e `down -v`, inclusive a ressalva da retenção do tópico.
- **AC-T007.4** A regra de README vivo está no `AGENTS.md` e no `05-harness.md` (Q-054), e o Status do README reflete o backlog real.
- **AC-T007.5** Nenhum segredo real no README (só os valores de desenvolvimento do `.env.example`). Nenhum comando derruba ou altera uma stack que não seja a criada pelo próprio passo a passo.
