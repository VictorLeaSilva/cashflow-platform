## Objetivo
Repositório Maven multi-módulo compilando em Java 25 com versões pinadas.

## Entradas
`00-constitution §3, §4`; `03-design-contracts §9`.

## Decisões da tarefa
- Spring Boot **4.1.1** (primeira patch confirmada em release; atualizar para a última patch ao rodar a T-001 é permitido, desde que o verify passe). Fallback 4.0.x só com ADR.
- POM raiz usa `spring-boot-starter-parent` como *parent* (BOM + versões de plugins gerenciadas); o `maven-enforcer-plugin` tem versão explícita.
- `groupId` `br.com.fluxocaixa`; pacotes `br.com.fluxocaixa.lancamentos` e `br.com.fluxocaixa.consolidado` (Q-004).
- Maven Wrapper em modo `only-script` (sem JAR binário versionado), gerado uma vez com `mvn wrapper:wrapper -Dtype=only-script -Dmaven=3.9.11`; os arquivos `mvnw`, `mvnw.cmd` e `.mvn/` entram no mesmo commit.
- Os serviços começam só com `spring-boot-starter` (sem web/JDBC/Kafka): cada capacidade entra na tarefa que a exige.
- O Failsafe só nasce na T-002; por isso a prova de compatibilidade (AC-T001.4) é um teste `*Test` rodado pelo Surefire e exige Docker no `verify`.

## Saídas
- POM pai com enforcer (Java ≥ 25, Maven ≥ 3.9, convergência de dependências, sem versões duplicadas).
- Módulos: `contracts` (só recursos), `lancamentos-service`, `consolidado-service` (cada serviço com `Application` mínima, teste `contextLoads` e `PlatformCompatibilityTest`).
- Regra de enforcer em cada serviço proibindo dependência do outro serviço.
- `.editorconfig` (2 espaços, alinhado ao google-java-format da T-002), `.gitignore`, `.gitattributes`, `LICENSE` (MIT), `README.md` provisório.
- `open-questions.md` com Q-001 e Q-004 resolvidas.

## Critérios de aceite
- **AC-T001.1** `./mvnw -q verify` verde em clone limpo (Java 25, Docker disponível).
- **AC-T001.2** O enforcer falha com Java < 25 (teste manual documentado no PR).
- **AC-T001.3** Os serviços não dependem um do outro: garantido pela regra `ban-peer-service` do enforcer (verificada ao adicionar temporariamente a dependência e ver o build falhar).
- **AC-T001.4** `PlatformCompatibilityTest` passa nos dois serviços (PostgreSQL e Kafka sobem via Testcontainers com as versões gerenciadas pelo BOM). Se falhar por incompatibilidade, aplicar o fallback 4.0.x via ADR.

## Testes exigidos
`contextLoads` por serviço (`@Tag("RNF-009")`) e `PlatformCompatibilityTest` (`@Tag("RNF-008")`).

## Não-objetivos
Lógica de negócio, Docker/compose, CI e linters (T-002/T-004), dependências de observabilidade/segurança/dados.
