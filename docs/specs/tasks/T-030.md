## Objetivo
Provar automaticamente que o evento `LancamentoRegistrado.v1` que o **Lançamentos produz** é o mesmo que o **Consolidado aceita**: os dois lados validam o mesmo JSON Schema (`contracts`) e os mesmos exemplos *golden*. Hoje só o consumidor valida (T-022); o produtor monta o evento (`LancamentoRegistradoV1`) sem nenhum teste contra o schema.

## Entradas
- `03-design-contracts` §4 (evento, regras de evolução) e §4.1 (`dataReferencia`).
- `04-quality-standards` §2.3, linha "Contrato de evento": "Produtor gera e consumidor aceita os mesmos exemplos".
- ADR-004 (JSON + JSON Schema, validado nos dois lados).
- `open-questions`: Q-006 (`networknt` 3.0.8), Q-043 (o Consolidado lê o schema do artefato `contracts`, com `format` conferido), **Q-059** (desta tarefa).
- Código: `lancamentos-service/.../application/LancamentoRegistradoV1.java` e o serializador da outbox; `consolidado-service/.../adapter/in/kafka/LeitorDeEvento.java`; `contracts/src/main/resources/{events,examples}/`; `consolidado-service/src/test/.../support/EventosJson.java`.

## Decisões da tarefa (Q-059, decidida em 2026-10-24)
- **Fonte única:** o Lançamentos passa a depender de `br.com.fluxocaixa:contracts` em **escopo de teste** e carrega o schema e os exemplos do *classpath*, do mesmo jeito que o Consolidado (Q-043). Nenhuma cópia do schema nos serviços.
- **Validação só em teste no produtor:** o evento nasce de um domínio já validado, e o teste cobre os três tipos. A validação em tempo de execução no Lançamentos continua fora (Q-006).
- **Golden files:**
  - criar `contracts/src/main/resources/examples/lancamento-registrado.v1.debito.json`, ao lado dos exemplos de crédito e estorno que já existem;
  - criar `contracts/src/main/resources/examples/invalidos/` com um arquivo por violação (por exemplo, `estorno-sem-tipo-original.json`, `valor-com-tres-casas.json`, `propriedade-extra.json`, `data-referencia-invalida.json`, `schema-version-2.json`). Cada arquivo tem, num `README` da pasta ou no próprio nome, a violação que representa.
- **Igualdade exata no produtor:** com `Clock` e `IdGenerator` fixos e a mesma entrada do exemplo, o JSON que vai para a outbox é **igual** ao *golden* (comparação de árvore JSON, sem ignorar campos). Se um campo opcional (`traceId`) não estiver no exemplo, o teste produz o evento sem ele.

## Saídas
- Teste de contrato do produtor no Lançamentos (`ContratoDoEventoTest`, ou o nome que seguir o padrão do pacote): os três *golden* validam no schema; o evento produzido é igual a cada *golden*; cada inválido é rejeitado pelo schema.
- No Consolidado: os inválidos de `contracts` vão para a DLT sem nova tentativa (Q-045) e não mudam a projeção; o *golden* de débito é aplicado com o efeito da regra (`03 §3.2`).
- Novos exemplos em `contracts/src/main/resources/examples/`.

## Critérios de aceite
- **AC-T030.1** Os três exemplos *golden* (crédito, débito e estorno) validam no schema dos dois lados, com `format` conferido (Q-043).
- **AC-T030.2** Para cada *golden*, o Lançamentos, com `Clock` e `IdGenerator` fixos, produz exatamente o mesmo JSON (árvore igual) na `outbox_event.payload`.
- **AC-T030.3** Cada exemplo de `examples/invalidos/` é rejeitado pelo schema no Lançamentos, e no Consolidado vai para a DLT na primeira tentativa, sem alterar `consolidado_diario` nem `evento_processado`.
- **AC-T030.4** Mudar um nome de campo no produtor, ou acrescentar um campo obrigatório no schema, quebra um teste de contrato. A prova é uma mutação manual registrada na evidência: muda, roda, falha, desfaz.
- **AC-T030.5** Nenhuma cópia de `lancamento-registrado.v1.schema.json` fora de `contracts/` (busca registrada na evidência).

## Testes exigidos
`@Tag("RF-008")` em todos. Unitário no produtor (sem Spring, se possível); no consumidor, IT com Testcontainers só para a DLT (reaproveitar a base de `DltIT`).

## Não-objetivos
Validação em tempo de execução no produtor; Schema Registry; versão `v2` do evento; mudança no schema.

## Armadilhas conhecidas
- O `contracts` precisa estar instalado no `~/.m2` (`./mvnw -q install -DskipTests`) para o Lançamentos achar o artefato fora do *reactor*.
- `networknt` 3.x: as violações vêm em JSON Pointer; use a mesma configuração de `format` do `LeitorDeEvento`, senão `uuid` e `date` não são conferidos.
- Decimal como string: compare `"valor":"100.00"` como texto, nunca como número.
