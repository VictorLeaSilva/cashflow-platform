## Objetivo
A banca deve ver, em minutos e sem UI, as garantias centrais funcionando, com os **dois serviços de verdade ao mesmo tempo**: idempotência, estorno, retroativo, isolamento por comerciante, Consolidado parado e, opcionalmente, Kafka parado. Esta tarefa também entrega o caminho de **5 comandos** da RNF-009 e da constituição §8, e é a prova cruzada que a T-031 deixou para cá (Q-060).

- `scripts/demo.sh` (rascunho de 168 linhas, ainda não executado contra a stack real).

## Decisões da tarefa
### Imagens e profile `apps` (Q-064, em proposta)
- **Imagens:** `spring-boot:build-image` (Paketo, usuário não-root por padrão), nomes `fluxo-caixa/lancamentos:<versão do projeto>` e `fluxo-caixa/consolidado:<versão do projeto>`. Sem Dockerfile próprio.
- **Serviços `lancamentos` e `consolidado`** no profile `apps`, com o profile Spring `local` e variáveis de ambiente que trocam só o que muda dentro da rede do compose: URL do banco (`postgres:5432`), *bootstrap* do Kafka (`kafka:29092`) e o caminho da chave pública JWT. Portas publicadas no host: 8081/9081 e 8082/9082 (as mesmas do Maven, então o Prometheus da T-032 funciona sem mudança).
- **Chave JWT antes dos serviços:** um serviço de execução única `dev-keys` (imagem `eclipse-temurin` 25 JDK, tag fixa) roda `scripts/DevToken.java` uma vez para criar `deploy/dev-keys/` se ainda não existir; `lancamentos` e `consolidado` dependem dele (`service_completed_successfully`) e montam a pasta só leitura.
- **Sem *healthcheck* nos contêineres dos serviços:** a imagem Paketo não tem `curl` nem *shell*. Quem espera a saúde é a `demo.sh` (e o README), consultando `:<gestão>/actuator/health` do host, com limite de tempo.

### `demo.sh` no Windows (Q-065, em proposta)
- A demo é **bash** e roda no Linux, no macOS e no **Git Bash** do Windows. No PowerShell, o README a chama pelo caminho do Git Bash, como o `verify-local.sh` (T-007).
- Dependências do host: `bash`, `curl`, `jq`, `java` e `docker`. No Windows, o `jq` vem do `winget install jqlang.jq` (instrução no README). O `uuidgen` sai: os UUIDs vêm de uma alternativa portátil (por exemplo, `java` ou `/proc/sys/kernel/random/uuid` com *fallback*).
- Sem `demo.ps1`: um segundo script dobraria a manutenção.

### Os 5 comandos (RNF-009)
1. `git clone ...` e `cd`; 2. `.env` a partir do `.env.example`; 3. compilar e gerar as imagens; 4. `docker compose --profile apps up -d --wait`; 5. `scripts/demo.sh`. O README ganha a seção **"Veja funcionando em 5 minutos"** com esses comandos, nos dois *shells*; o passo a passo detalhado pelo Maven (T-007) continua.

## Critérios de aceite
- **AC-T035.1** Numa stack limpa (isolada), os 5 comandos levam a `demo.sh` a terminar com exit 0, cada passo com asserção explícita (status HTTP, campos do JSON, totais do consolidado).
- **AC-T035.2** Com `--kafka-down`, também exit 0: o Kafka é parado, os POSTs seguem 201, a outbox acumula, o Kafka volta e o consolidado converge.
- **AC-T035.3** O passo "Consolidado parado" para o contêiner `consolidado`, mostra POSTs com 201, sobe o contêiner de novo e confere a convergência.
- **AC-T035.4** Se o script falhar no meio, o `trap` religa o Consolidado e o Kafka antes de sair.
- **AC-T035.5** Cada execução usa comerciantes novos; rodar duas vezes seguidas dá exit 0 nas duas.
- **AC-T035.6** Os contêineres dos serviços rodam como usuário não-root (`docker inspect` ou `id -u` registrado na evidência).
- **AC-T035.7** `bash -n` e `shellcheck` sem achados (o `shellcheck` pode rodar pela imagem `koalaman/shellcheck`, tag fixa); o job `demo.yml` passa ao menos uma vez (link da execução, ou a execução local equivalente na evidência).
- **AC-T035.8** README executado nos dois *shells* (no PowerShell, a demo pelo Git Bash) e o "o que você deve ver" conferido.

## Armadilhas conhecidas
- O `build-image` baixa o *builder* do Paketo (centenas de MB) na primeira vez; o tempo fica fora das medições.
- No Git Bash, caminhos começando com `/` passados ao `docker` são convertidos pelo MSYS (`/opt/...` vira `C:/Program Files/Git/opt/...`); use `MSYS_NO_PATHCONV=1` dentro do script quando chamar `docker exec` com caminho absoluto.
- `--remove-orphans` no `up` da demo pode remover contêineres de outros profiles do mesmo projeto: teste com o `observability` ligado.
- Nunca derrube a stack `fluxo-caixa` do autor: a demo usa o projeto do compose corrente, e a verificação usa `COMPOSE_PROJECT_NAME` isolado (`05 §3`).
